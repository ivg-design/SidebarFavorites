2 · The mode picker

Advanced mode states its costs — and its name

Lives in each favorite's settings: toggling converts the favorite in place, either direction. Regular → Advanced generates and enables the helper; Advanced → Regular removes it and the row falls back to the built-in glyph instantly. Round-trip verified live on the real github favorite.

The helper block answers the three questions users actually ask: is it on, what does it cost, what happens if it breaks. The System Settings preview teaches recognition before the user ever opens Settings.

Hard requirement, verified live: every generated extension is named SBF-[Name] and carries the app icon in the Settings pane.
No Settings trip needed to enable: pluginkit -e use works, including ad-hoc-signed helpers on machines with no developer certificate.
SF Symbols and custom SVGs both work in both modes, from one artwork source, through one renderer — identical glyphs, verified side-by-side.
Custom SVG artwork ships via the app's own CoreThemeCatalogWriter — no Xcode required.
Drives & SMB shares decorate too; unmount/remount self-heals via the helper's re-registration toggle.

3 · The detection flow

Today's remove-only dialog becomes a real choice

Shown only when adding a favorite whose folder already has its own icon. A folder with no custom icon is added in Regular mode silently — today's exact behavior, zero new friction. The recommended path is the new mode; removal stays for users who prefer zero helpers.

Icon restore obeys the fresh-folder rule: never decorate a folder < 30 s old; verify ~20 s after applying and re-apply once.
Removal keeps using the existing IconAuthority backup path.
